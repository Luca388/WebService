# WEEK 09 · 실습 2 구현·검증 체크리스트

현재 코드를 기준으로 정리한 상태이다. ✅는 관련 코드가 구현되어 있다는 뜻이며, 실제 테스트 통과를 의미하지 않는다. 각 항목의 구현·보완과 실제 검증을 마친 뒤 확인 칸을 ☐에서 ☑로 변경한다.

| 확인 | 평가 항목 | 요구사항 | 현재 상태 |
| :---: | --- | --- | --- |
| ☐ | 검색·정렬 | 제목·본문 검색, 결과 없음 처리 | ✅ 구현됨 — 오프셋 모드 |
| ☑ | 검색·정렬 | 최신순·오래된순·조회순 | ✅ 최신순은 작성일 DESC·ID DESC, 오래된순은 작성일 ASC·ID ASC, 조회순은 조회수 DESC·ID DESC. API 처리 함수 테스트에서 정렬별 1,000건·10페이지 순서 및 동점 처리 확인. 브라우저 캡처는 별도 필요 |
| ☑ | 검색·정렬 | 조회수 동점은 `id DESC` | ✅ 같은 조회수를 갖는 테스트 데이터로 API 처리 함수 검증 완료 |
| ☐ | 검색·정렬 | 잘못된 정렬 키는 `latest` 처리 | ⚠️ 일반적인 잘못된 값은 처리하지만 상속 속성은 처리하지 못함 |
| ☐ | 검색·정렬 | `__proto__`, `constructor` 차단 | ❌ 빠져 있음 |
| ☐ | 페이지네이션 | 오프셋 페이지 이동, `meta` 응답 | ✅ 구현됨 |
| ☐ | 페이지네이션 | `page=0, -1, abc`, `limit=1000` 처리 | ✅ 서버에 구현됨 |
| ☐ | 페이지네이션 | 검색·정렬 변경 시 1페이지 초기화 | ✅ 구현됨 |
| ☐ | 페이지네이션 | 커서 API의 제목·본문 검색 | ❌ 빠져 있음 — 프론트도 검색어를 보내지 않음 |
| ☐ | 페이지네이션 | 검색·커서 조건 적용 후 `limit + 1` | ⚠️ 커서 조건과 `limit + 1`은 구현됨. 검색 조건은 없음 |
| ☐ | 페이지네이션 | 커서 ID 내림차순, 정렬 선택 비활성화 또는 기준 명시 | ⚠️ ID 내림차순은 구현됨. 정렬 선택창 처리는 빠져 있음 |
| ☐ | 페이지네이션 | 검색어 변경 시 누적 목록·커서 초기화 | ⚠️ 커서는 초기화하고 목록은 응답 후 초기화함. 검색 기능과 함께 보완 필요 |
| ☐ | 페이지네이션 | 끝까지 누락·중복 없음 | 🧪 전체 조회 테스트 필요 |
| ☐ | 페이지네이션 | `hasNext=false`일 때 더 보기 비활성화 | ✅ 구현됨 |
| ☐ | 비동기 | 300ms 디바운스 | ✅ 구현됨 — 요청 1회인지 측정 필요 |
| ☐ | 비동기 | 이전 요청 취소·오래된 응답 방지 | ⚠️ 새 요청 시작 시 취소는 구현됨. 디바운스 대기 중 이전 응답이 반영될 수 있어 보완 필요 |
| ☐ | 비동기 | `AbortError` 안전 처리 | ✅ 구현됨 |
| ☐ | 비동기 | 느린 네트워크에서 취소·최종 결과 검증 | 🧪 테스트 필요 |
| ☐ | URL 복원 | 검색어·정렬·페이지 URL 동기화 | ✅ 기본 구현됨 |
| ☐ | URL 복원 | 새로고침·뒤로 가기 후 URL과 화면 일치 | ⚠️ 기본 복원은 구현됨. 잘못된 값·범위 밖 페이지에서는 불일치 가능 |
